# Realty Parser

Сервис для сбора объявлений об аренде и продаже квартир. Периодически обходит страницы поиска по заданным фильтрам и сохраняет объявления вместе с заданиями для анализатора в SQLite.

## Что делает сервис

- Обходит страницы поиска ЦИАН по настроенным фильтрам (цена, площадь, количество комнат)
- Для каждого нового объявления извлекает полную информацию: цена, площадь, этаж, метро, условия аренды и т.д.
- Рассчитывает скоринговый балл объявления для удобства сортировки
- Сохраняет данные в SQLite (таблица `flats_history`)
- Атомарно сохраняет JSON-задание для каждого нового объявления в `flat_events`
- Уже виденные объявления пропускает — повторных записей нет

## Яндекс Недвижимость

Адаптер читает JSON первой страницы выдачи через веб-метод `/gate/react-page/get/` и передаёт найденные квартиры в тот же анализатор, что и объявления Циана. Для каждого региона из активных подписок используется соответствующий `rgid` Яндекса. Цена, площадь и комнаты дополнительно фильтруются локально. Источник приостанавливает обход до следующего цикла при капче или ограничении запросов.

```yaml
yandex:
  enabled: false
  regions:
    1: 587795  # Москва
```

Запрос к веб-методу при проверке вернул перенаправление на капчу. Адаптер проверен на локальных примерах JSON и по умолчанию выключен. Поля берутся из выдачи. Полный набор полей карточки, пагинация и формат условий долгосрочной аренды требуют проверки на живых ответах. В публичной документации Яндекса [партнёрский API](https://www.yandex.ru/support/realty-partner/ru/api-calls) описывает работу со звонками, а [XML-фид](https://www.yandex.ru/support/realty/ru/feed/account-xml-partners-housing) предназначен для передачи объявлений в Яндекс.

Миграция `002_cross_platform_listings.sql` добавляет адрес для новых объявлений и таблицу вторых ссылок. При ручном обновлении существующей SQLite-базы выполните `bash dev-tips/apply_migrations.sh` из корня проекта до запуска нового парсера. Сопоставление проверяет объявления другой площадки за последние 30 дней. Сравниваются регион, тип сделки, точная цена, этаж, комнатность, общая площадь с допуском 0,5 м² и жилая или кухонная площадь. Дом подтверждается нормализованным адресом либо координатами в пределах 25 м. При единственном совпадении первое объявление остаётся в выдаче, а вторая ссылка и распознанные поля сохраняются в `flat_listing_aliases`. Для совпадения отправляется одно событие.

## Конфигурация

Все настройки задаются в `config.yaml`:

```yaml
search:
  min_price: 50000       # минимальная цена аренды
  max_price: 85000       # максимальная цена
  min_area: 38           # минимальная площадь
  rooms: [2, 3, 4]       # типы комнатности (2=1к, 3=2к, 4=3к)
  pages_limit: 1         # максимум страниц за один обход
  overall_limit: 20      # максимум объявлений за один обход

worker:
  period_seconds: 10            # интервал между обходами
  request_timeout_ms: 5000      # таймаут HTTP-запроса
  sleep_before_request_ms: 3000 # пауза перед каждым запросом к объявлению
  max_retries: 5                # количество повторных попыток при ошибке
  cookie_header: ""             # cookie сессии браузера (обновлять при блокировке)

database:
  dsn: "file:/data/realtyranker.db?mode=rw"

logging:
  file_path: "/var/log/realty-parser/app.log"
  level: "debug"   # debug / info / warn / error

metrics:
  port: 9095
```

## Запуск в Docker

Сервис запускается в контейнере в рамках общей Docker-сети `realty-net`. Общий volume SQLite должен быть инициализирован — см. инструкцию в `dev-tips/`.

```bash
bash server_setup.sh
```

Собирает Docker-образ и запускает контейнер `realty-parser`. Логи пишутся в `/tmp/realty-parser-logs/` на хосте.

```
# Логи:
docker logs -f realty-parser

# Остановить:
docker stop realty-parser
```

Общий файл БД монтируется в `/data` через volume `realtyranker_sqlitedata`.
Схема, перенос прежних данных и резервное копирование описаны в [dev-tips](../dev-tips/README.md).
